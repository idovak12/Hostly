# דשבורד האולם

ממשק עבודה לבעל אולם אירועים: אירועים, אישורי הגעה, הושבה, תשלומים מזוגות, חשבונות ספקים והוצאות קבועות.
קובץ HTML אחד בלי בנייה. הנתונים נשמרים ב-Supabase, וכל חשבון רואה רק את האולם שלו.

## הקבצים
- `index.html` – כל הדשבורד.
- `config.js` – הכתובת והמפתח של פרויקט ה-Supabase. כשהם ריקים, הדף עובד כהדגמה.
- `schema.sql` – הטבלה וכללי הגישה. מריצים פעם אחת.

## הקמה (בערך 10 דקות)
1. פותחים חשבון ב-supabase.com ויוצרים פרויקט חדש.
2. ב-SQL Editor מדביקים את `schema.sql` ולוחצים Run.
3. ב-Project Settings → API מעתיקים את Project URL ואת ה-anon public key לתוך `config.js`.
4. מעלים את התיקייה לאחסון סטטי, למשל Netlify (גוררים את התיקייה ל-app.netlify.com/drop), Vercel או Cloudflare Pages.
5. ב-Supabase, ב-Authentication → URL Configuration, מגדירים את Site URL לכתובת האתר, כדי שקישור אישור המייל יחזיר לשם.
6. נכנסים לאתר, לוחצים "הרשמת אולם חדש" וממלאים שם אולם, עיר, איש קשר, טלפון, מייל וסיסמה. מאשרים את המייל ונכנסים: נוצר אולם עם הפרטים האלה, בלי אירועים.

## הדגמה
מוסיפים `?demo` לכתובת, או משאירים את `config.js` ריק. ההדגמה לא נשמרת בשום מקום.

## איך השמירה עובדת
- כל האולם נשמר כרשומה אחת (`halls.data`). שינוי נשמר כחצי שנייה אחרי שנעשה, והסטטוס מופיע בפס העליון.
- לכל רשומה יש מספר גרסה. אם מכשיר אחר שמר בינתיים, הדף לא דורס את השינוי שלו: הוא מתריע וטוען את הגרסה העדכנית.
- אין אפשרות למחוק את האולם מהדף.

## רשימת מוזמנים מקובץ
באירוע, בטאב "אישורי הגעה": "העלאת קובץ". נתמכים אקסל (xlsx, xls), CSV ווורד (docx, טבלה או שורה לכל משפחה).
העמודות שמזוהות: שם, כמות, צד, טלפון, סטטוס (מגיע / לא מגיע). רק שם חובה. לפני השמירה מוצגת תצוגה מקדימה,
ואפשר להוסיף לרשימה הקיימת או להחליף אותה. "קובץ דוגמה" מוריד תבנית מוכנה.

## הוצאות קבועות
במרכז השליטה: חודשיות (שכר, חשמל) או שנתיות (רואה חשבון, ביטוח) עם חודש תשלום. הוצאה שנתית מופיעה רק בחודש שלה.

## מה עוד לא קיים
- אישורי הגעה מהזוג עצמו (הצד של הזוג עוד לא נבנה). רשימת המוזמנים נכנסת בינתיים מקובץ.
- חשבון אחד לכל אולם. אין עדיין הזמנת אנשי צוות לאותו אולם.
- אין מחיקה או ארכוב של אירוע.
